# 演示脚本（10 分钟）

> 目标：不念代码，用一条完整路径讲清楚“校园地点社区 + 路线”这件事。
> 前置：`docker compose up -d` 已跑通；准备两个账号（普通用户 `seed_chen`、管理员 `seed_lin`，密码都是 `secret123`）。

## 0. 一句话开场（30 秒）

> roam-bupt 是一个“帖子挂地点”的校园社区：内容不是按板块分，而是按**地点**聚；帖子里的地点有顺序，所以一条帖子能直接变成一条路线。

## 1. 首页（1 分钟）

- 左栏：全部 67 个地点，按分类（住宿 32 / 服务 16 / 地标 6…）。
- 右栏：「这周人多的地方」是真实热度——发帖会给地点加热。
- 信息流：帖子卡片带地点标签。

**要讲的点**：地点是主题的一种（`topic.type=PLACE`），不是单独的实体，避免两套体系。

## 2. 地点页（1 分钟）

- 打开「教三楼」：内容聚合、热度、评分。
- 点星星打分：均分是贝叶斯平滑，一条 5 星不会把均分顶到 5。

**要讲的点**：评分挂地点不挂帖子，读者 × 地点唯一键，重复打分是改分。

> 彩排提示：生产配置 `auto-approve=false`，发布后帖子是 `PENDING`，**必须切管理员在 /admin/posts 通过审核**，游客和其他用户才能看到。彩排时这一步是第 4 段。

## 3. 发帖（2 分钟）

- 写标题正文，传一张图。
- 搜「教三」「食堂」挂两个地点，**顺序就是路线顺序**。
- 发布后跳详情，图片、地点链、作者都在。

**要讲的点**：上传做了大小/类型/魔数三重校验，拒绝 svg；发帖媒体 URL 必须是站内前缀。

## 4. 搜索（1 分钟）

- 搜「教三」：ES 召回，展示回读 MySQL。
- 现场可以把 ES 停掉（`docker compose stop elasticsearch`），再搜一次——仍然有结果，只是日志里有 `search.es.fallback`，健康检查仍是 UP。

**要讲的点**：软依赖不该拖垮整站；健康检查只判硬依赖。

## 5. 路线（2 分钟）

- 路线页：底图 372 节点 / 446 边，选「教三楼 → 学生食堂」，出 3 条方案，按耗时排序。
- 选一条，地图上高亮折线。
- 回帖子里点「按这个顺序走」，三个地点串成一条路线（彩排用的是帖子 24「校园里最适合发呆的三个角落」，3 个地点）。

**要讲的点**：

- 寻路是纯函数（Dijkstra + 禁边重算），图与拥挤度从外面注入，测试不用起 Spring；
- 拥挤度按分钟桶记录，公式 `1 + k·u/(1-u)`；连续问同一条路，系数会涨（可以现场连点几次再规划，看数字变化）。

## 6. 互动与通知（1 分钟）

- 给别人的帖子点赞、评论。
- 切到通知页：未读角标、点一条已读后角标减一。

**要讲的点**：点赞用唯一键做幂等，重复点不重复通知；通知是事件驱动，同事务写入。

## 7. 个人主页与关注（1 分钟）

- 打开作者主页，关注。
- 首页切「关注」tab，只剩关注的人的内容。

## 8. 后台（1 分钟）

- 管理员登录，顶栏出现「后台」。
- 内容审核：`PENDING → ONLINE`；用户管理可封禁（对方旧 token 立即 401）；敏感词维护。

**要讲的点**：权限用注解 + 拦截器，角色每请求查库，所以封禁立即生效。

## 9. 收尾（30 秒）

> 技术上四个模块（api/core/service/web），跨域只走 QueryService；事件驱动做通知与索引；可降级依赖（ES）不参与健康判定；幂等靠唯一键，不靠 if。

## 备用问答

| 可能被问 | 回答要点 |
|---|---|
| 为什么不用 Redis 存点赞计数 | 量级没到，实时 COUNT 更不容易错；待观察里写了触发条件 |
| ES 挂了搜索变慢怎么办 | 降级层加超时/并发上限/熔断，触发条件写在实现清单「待观察」 |
| 路线为什么不用真地图 | 只有底图比例坐标；要真地图只需地理配准或 Overpass 重建，二选一 |
| 头像/封面为什么空 | 数据导出时就没有，P3 补种子 |
