# 部署与回滚（Q5）

> 目标：一台装了 Docker 的机器，三条命令把 roam-bupt 跑起来；出问题能退回上一版。

## 1. 前置

- Docker Engine 20.10+ / Docker Desktop
- Docker Compose v2（`docker compose version` 能打印版本）
- 空闲端口：3306、6379、9200、8080、8081

## 2. 首次启动

```bash
cd roam-bupt
cp .env.example .env
# 改 .env：MySQL/Redis 密码、ROAM_JWT_SECRET（至少 32 字节）
docker compose up -d --build
```

启动顺序由 healthcheck 保证：

```
mysql(healthy) → redis(healthy) → elasticsearch(healthy) → backend(healthy) → frontend
```

后端起来时 Liquibase 会自动建表并导入种子数据（152 个主题、372 个路网节点、446 条边），**不需要手工执行 SQL**。

打开 `http://localhost:8081`。

### VM 同步代码

VM 的 `origin` 走 **SSH**（`git@github.com:Thereia/roam-bupt.git`），VM 上已生成 `~/.ssh/github_roam` 并写进 `~/.ssh/config`；
公钥加在 GitHub 账号后，`ssh -T git@github.com` 返回 `Hi Thereia!` 即通。SSH 比 HTTPS 稳（这台 VM 的 HTTPS 会报 GnuTLS/连接拒绝）。

```bash
ssh root@192.168.153.129 "cd ~/roam-bupt \
  && git update-index --no-skip-worktree docker-compose.yml \
  && git checkout -- docker-compose.yml \
  && git fetch origin && git reset --hard origin/main \
  && bash scripts/apply-vm-ports.sh \
  && git update-index --skip-worktree docker-compose.yml"
```

`docker-compose.yml` 的端口映射是 VM 上唯一需要保留的改动，所以每次同步前先放开、同步后重打并 `skip-worktree`。

如果 SSH 也拉不动（极端情况），用 bundle 兜底：

```bash
git bundle create /tmp/sync.git --all
scp /tmp/sync.git root@192.168.153.129:/tmp/
ssh root@192.168.153.129 "cd ~/roam-bupt \
  && git update-index --no-skip-worktree docker-compose.yml \
  && git checkout -- docker-compose.yml \
  && git fetch /tmp/sync.git 'refs/heads/*:refs/remotes/bundle/*' \
  && git reset --hard refs/remotes/bundle/main \
  && bash scripts/apply-vm-ports.sh \
  && git update-index --skip-worktree docker-compose.yml"
```

## 3. 环境变量

| 变量 | 作用 | 默认 |
|---|---|---|
| `MYSQL_ROOT_PASSWORD` | MySQL root 密码 | `123456` |
| `REDIS_PASSWORD` | Redis 密码 | `123456` |
| `ROAM_JWT_SECRET` | JWT 签名密钥，**必须改**，至少 32 字节 | 无（不设会启动失败） |
| `ROAM_WRITE_PER_MINUTE` | 每用户/IP 每分钟写操作上限 | `30` |
| `ROAM_TRUST_XFF` | 是否信任 `X-Forwarded-For`（容器在 nginx 后） | `true` |
| `ROAM_UPLOAD_DIR` | 上传目录（挂卷） | `/app/uploads` |

## 5. 升级

```bash
git pull
docker compose build backend frontend
docker compose up -d
```

- 数据库变更由 Liquibase changeset 自动应用；
- 后端是滚动替换（先起新的、健康后再换），单机 compose 会有几秒不可用；
- 前端重新构建后 nginx 直接换静态文件。

## 6. 回滚

**代码回滚**

```bash
git checkout <上一个可以用的 tag 或 commit>
docker compose build backend frontend
docker compose up -d
```

**数据回滚**（Liquibase 只前进，不自动回退）

```bash
# 升级前先备份
docker compose exec mysql sh -c 'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" roam_bupt' > backup-$(date +%F).sql

# 需要回滚时
docker compose exec -T mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" roam_bupt' < backup-2026-11-22.sql
```

上传的图片在 `uploads-data` 卷里，备份卷：

```bash
docker run --rm -v roam-bupt_uploads-data:/data -v "$PWD":/backup alpine \
  tar czf /backup/uploads-$(date +%F).tar.gz -C /data .
```

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| backend 起不来，日志有 `ROAM_JWT_SECRET` | 没配 secret | 在 `.env` 里设置至少 32 字节的随机串 |
| 3306/8080 端口被占用 | 本机已有 MySQL/服务 | 改 compose 左侧端口，如 `"13306:3306"` |
| ES 容器反复重启 | 内存不足 | 降低 `ES_JAVA_OPTS` 或给 Docker 至少 2GB |
| 首页 502 | backend 还没 healthy | `docker compose logs -f backend` 看是不是 Liquibase 在导入 |
| 上传后图片 404 | 卷没挂上 | 确认 `uploads-data:/app/uploads` 存在 |
| 新帖发了看不到了 | 生产 `auto-approve=false` | 用管理员账号在 `/admin/posts` 通过审核 |

## 8. 演练记录（2026-11-22，VM 上实测）

**数据回滚**

```
回滚前：post = 24
模拟误操作：DELETE FROM post ORDER BY id LIMIT 5  → 19
用 /root/roam-backup.sql 恢复                          → 24
```

结论：`mysqldump` 备份可用，恢复后行数与回滚前一致。备份前先跑一次「导入临时库核对行数」更稳（本次做过：84K 的 dump 导入 `roam_verify` 后 24 帖 / 4 用户 / 152 主题）。

**配置回滚**

```
把 .env 里 ROAM_JWT_SECRET 改成 short
  → docker compose up -d --force-recreate backend
  → 容器 Exited (1)，health 不可达
恢复 .env → up -d --force-recreate backend
  → Up (healthy)，health 返回 UP
```

结论：坏配置的失败是**启动即退出**，不会带病运行；回滚只需恢复 `.env` 再重建容器，不需要动数据。

**镜像回滚（未完成）**

演练时 VM 的 DNS 故障（`docker.m.daocloud.io` 与 `registry-1.docker.io` 均解析失败），无法重新构建镜像，因此「打 tag → 发布新镜像 → 退回旧 tag」这一路径**没有实际走通**。步骤仍按第 6 节执行，待网络恢复后补做。

**演练中修掉的问题**

- nginx 的静态资源正则 `~* \.(png|jpg…)$` 抢在 `location /files/` 前面，导致上传图片经 8080 正常、经 8081 返回 404。已给 `/api/`、`/files/` 加 `^~` 前缀匹配（前缀命中后不再走正则）。
- 同时把 `nginx.conf` 改成 compose 挂载（`./frontend/nginx.conf:/etc/nginx/conf.d/default.conf:ro`），以后改缓存/反代规则不用重建镜像。

## 9. 已知环境问题

- **VM 突然没有外网**：症状是 DNS 全部解析失败、`curl` 超时、`docker build` 卡在 `resolve source metadata`。根因通常不是 DNS 配置，而是 Windows 上的 **VMware NAT Service 停止转发**。修法（管理员 PowerShell）：

  ```powershell
  Restart-Service 'VMware NAT Service' -Force
  ```

  重启后 `getent hosts www.baidu.com` 应能解析、`curl https://www.baidu.com` 返回 200。


- VM 的 `/etc/resolv.conf` 指向 `127.0.0.53`（systemd-resolved），本身正常；出问题先按上一条查 NAT 服务。
