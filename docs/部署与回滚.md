# 部署与回滚（Q5）

> 目标：一台装了 Docker 的机器，三条命令把 roam-bupt 跑起来；出问题能退回上一版。

## 1. 前置

- Docker Engine 20.10+ / Docker Desktop
- Docker Compose v2（`docker compose version` 能打印版本）
- 空闲端口：3306、6379、9200、8080、8081

## 2. 首次启动

```bash
cd roam-bupt
cp .env.example .env
# 改 .env：MySQL/Redis 密码、ROAM_JWT_SECRET（至少 32 字节）
docker compose up -d --build
```

启动顺序由 healthcheck 保证：

```
mysql(healthy) → redis(healthy) → elasticsearch(healthy) → backend(healthy) → frontend
```

后端起来时 Liquibase 会自动建表并导入种子数据（152 个主题、372 个路网节点、446 条边），**不需要手工执行 SQL**。

打开 `http://localhost:8081`。

## 3. 环境变量

| 变量 | 作用 | 默认 |
|---|---|---|
| `MYSQL_ROOT_PASSWORD` | MySQL root 密码 | `123456` |
| `REDIS_PASSWORD` | Redis 密码 | `123456` |
| `ROAM_JWT_SECRET` | JWT 签名密钥，**必须改**，至少 32 字节 | 无（不设会启动失败） |
| `ROAM_WRITE_PER_MINUTE` | 每用户/IP 每分钟写操作上限 | `30` |
| `ROAM_TRUST_XFF` | 是否信任 `X-Forwarded-For`（容器在 nginx 后） | `true` |
| `ROAM_UPLOAD_DIR` | 上传目录（挂卷） | `/app/uploads` |


## 4. 启动后的验证清单

```bash
# 1) 后端健康（只判硬依赖，ES 挂了也应是 UP）
curl -s http://localhost:8080/actuator/health        # {"status":"UP"}

# 2) 首页数据
curl -s "http://localhost:8080/api/v1/posts?pageSize=1" | head -c 120

# 3) 路网导入
curl -s "http://localhost:8080/api/v1/nav/map" | python -c "import sys,json;d=json.load(sys.stdin)['data'];print(len(d['nodes']), len(d['edges']))"
# 期望 372 446

# 4) 搜索（ES 正常时走 ES，异常自动降级 MySQL）
curl -s "http://localhost:8080/api/v1/search?q=%E6%95%99%E4%B8%89" | head -c 100

# 5) 前端
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8081/
```

浏览器里再走一遍：注册 → 登录 → 发帖（带图）→ 首页可见 → 搜索到 → 打开路线页选两个地点。

## 5. 升级

```bash
git pull
docker compose build backend frontend
docker compose up -d
```

- 数据库变更由 Liquibase changeset 自动应用；
- 后端是滚动替换（先起新的、健康后再换），单机 compose 会有几秒不可用；
- 前端重新构建后 nginx 直接换静态文件。

## 6. 回滚

**代码回滚**

```bash
git checkout <上一个可以用的 tag 或 commit>
docker compose build backend frontend
docker compose up -d
```

**数据回滚**（Liquibase 只前进，不自动回退）

```bash
# 升级前先备份
docker compose exec mysql sh -c 'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" roam_bupt' > backup-$(date +%F).sql

# 需要回滚时
docker compose exec -T mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" roam_bupt' < backup-2026-11-22.sql
```

上传的图片在 `uploads-data` 卷里，备份卷：

```bash
docker run --rm -v roam-bupt_uploads-data:/data -v "$PWD":/backup alpine \
  tar czf /backup/uploads-$(date +%F).tar.gz -C /data .
```

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| backend 起不来，日志有 `ROAM_JWT_SECRET` | 没配 secret | 在 `.env` 里设置至少 32 字节的随机串 |
| 3306/8080 端口被占用 | 本机已有 MySQL/服务 | 改 compose 左侧端口，如 `"13306:3306"` |
| ES 容器反复重启 | 内存不足 | 降低 `ES_JAVA_OPTS` 或给 Docker 至少 2GB |
| 首页 502 | backend 还没 healthy | `docker compose logs -f backend` 看是不是 Liquibase 在导入 |
| 上传后图片 404 | 卷没挂上 | 确认 `uploads-data:/app/uploads` 存在 |
| 新帖发了看不到了 | 生产 `auto-approve=false` | 用管理员账号在 `/admin/posts` 通过审核 |
