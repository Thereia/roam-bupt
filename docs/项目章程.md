# roam-bupt 项目章程

> 状态：草案 v1（2026-11-17），依据界面示意 `docs/mockup.html` 与逐轮讨论结论收敛而来。
> 变更方式：改动任何一条"已定"项，先改本文件，再动代码。

---

## 1. 一句话定位

**以地点为锚的校园漫游社区：内容挂在地点上，地点能变成路线，路线能被走。**

不是论坛加地图，也不是地图加论坛。三样东西必须同时在：

| 腿 | 提供什么 | 来自 |
|---|---|---|
| 内容 | 帖子、评论、点赞/收藏/关注/通知、检索、后台 | taco 的内容骨架 |
| 地点 | 地点即主题，地点页聚合内容 + 评分 + 入口 | travel-bupt 的 POI |
| 路线 | 寻路、多方案、拥挤度、按顺序走 | travel-bupt 的图算法 |

## 2. 用户与场景

| 用户 | 场景 | 频率 |
|---|---|---|
| 在校生 | 找自习位/食堂/宿舍信息，发帖、看帖、收藏 | 高频 |
| 新生/访客 | 认路、按攻略走一遍校园 | 低频但强需求 |
| 活动参与者 | 校庆集章、社团招新、迎新跑的点位顺序 | 阶段性 |

**不做**：校外城市导航、多校区、校外用户运营。

## 3. 核心循环

```
写帖（挂 1..N 个地点主题）
   ↓
地点页聚合（内容流 + 评分 + 入口）
   ↓
「按这个顺序走」→ 现算路线（Dijkstra + 多方案 + 拥挤度）
   ↓
走完回到地点页，继续写
```

## 4. 范围

### 做（一期）

- 开放注册 / 登录 / 会话（JWT + Redis）
- 发帖：标题、正文、图片、挂多个主题（地点 + 分类）、多地点可排序
- 地点页（主题页）：内容流、评分、地点信息、`到这里怎么走`
- 帖子详情：正文、评论（两级）、点赞/收藏/关注、分享
- 首页：推荐 / 最新 / 关注；左栏分类，右栏热门地点与今日路线
- 搜索：关键词 + 地点过滤，ES 词级召回，MySQL 兜底
- 导航：起终点、步行/骑行/混合、多方案、分段拥挤度着色
- 评分：读者给地点打分（1–5，一人一地点一次，可改），均分贝叶斯平滑
- 通知：评论/回复/@/点赞/关注，站内
- 后台：内容审核、用户管理、敏感词、地点数据（只读）

### 不做（一期明确不做）

- 微信登录/支付/公众号/小程序、付费、专栏、知识星球、短链、SEO/sitemap
- 任何 AI / LLM 能力（另一个 LangChain 项目承接，避免简历重叠）
- turn-by-turn 实时导航、室内楼层导航、实时定位跟随
- 美食推荐
- 地点/路网的在线维护界面（数据静态导入，改动走 SQL）
- 向量召回（二期再看）

## 5. 数据模型

命名：库 `roam_bupt`，表 `snake_case`，时间字段 `created_time / updated_time`。

```
user            id, username, password(bcrypt), nickname, avatar, role(USER/ADMIN), status, created_time

topic           id, type(PLACE/CATEGORY), name, category, node_id, source_ref,
                cover, description, heat, enabled
                # PLACE 一行 = 一个地点，node_id 指向导航图入口节点
                # CATEGORY 一行 = 一个分类（食堂/自习/住宿/运动/教学楼）

post            id, user_id, title, content, status(DRAFT/PENDING/ONLINE/DELETED),
                heat, created_time, updated_time

post_topic      post_id, topic_id, sort_no          # 一条帖子挂多个主题；地点主题有序

post_media      id, post_id, media_type(IMAGE/VIDEO), url, sort_no

comment         id, post_id, user_id, content, parent_id, top_id, deleted, created_time

user_foot       id, user_id, post_id, action(LIKE/COLLECT), created_time
                # 唯一键 (user_id, post_id, action)

follow          id, user_id, target_user_id, created_time   # 唯一键 (user_id, target_user_id)

notification    id, user_id, type, source_id, content, read, created_time

topic_rating    id, user_id, topic_id, score(1..5), created_time, updated_time
                # 唯一键 (user_id, topic_id)

topic_rank      topic_id, default_score, heat_score, rating_score, calculated_at

# 导航图（从 travel-bupt 原样导入，静态）
route_node      node_id, name, type, x_ratio, y_ratio, building_id, floor, poi_category, enabled
route_edge      edge_id, from_node_id, to_node_id, distance_meters, time_seconds,
                edge_type, bike_allowed, congestion_factor, enabled
```

补充约定：

- **不建 `route` 表**。路线不落库：帖子只存"地点序列"，路径每次现算（可短 TTL 缓存）。
- **不建 `poi` 表**。地点就是 `topic(type=PLACE)`，避免与主题体系重复。
- 评分挂 `topic_rating`（读者 × 地点），不挂帖子，因此发帖时零负担。
- 均分 = 贝叶斯平滑（先验 10 条 3.5 分），避免"1 条 5 星排第一"。

## 6. 空间与算法

- 寻路：Dijkstra（距离/时间/混合三种权重）。
- 多方案：换权重 + 禁边重算，产出 2–3 条备选。
- 多地点：按 `post_topic.sort_no` 串行分段；未排序时用 DP 求近似最优顺序。
- 拥挤度：寻路成功即对该路径的边计数 → Redis 分钟桶 → TTL 过期 → 漏桶系数 `1 + K·u/(1-u)` → 边权放大。
- 无 turn-by-turn：只输出路径、分段、总距离/耗时、拥堵着色。

已知限制（写进 README，不藏）：

- 拥挤度信号是"问路次数"而非真实人流，用户少时不触发；演示用脚本压请求。
- 节点只有底图比例坐标（`x_ratio/y_ratio`），不是经纬度。底图 `map.png` 是 OSM 截图，二期用 2–3 个地标做仿射配准即可补出经纬度（详见 `docs/数据导出说明.md`）。

## 7. 技术栈与工程结构

- Spring Boot 3.5.16 / Java 17 / Maven 多模块
- MyBatis-Plus；MySQL 8；Redis；Elasticsearch 7.17（词级召回 + 兜底）；RabbitMQ（通知异步，默认开，带开关）
- Liquibase 管库结构；配置外部化（`.env` / 环境变量）
- 前端：Vue 3 + Vite（沿用 taco-vue 的壳），无重型 UI 库

```
roam-bupt/
├─ roam-api        实体 / DTO / VO / 枚举
├─ roam-core       基础设施：Redis、统一返回、异常、JWT、限流
├─ roam-service    业务：user / post / topic / comment / notify / search / space
├─ roam-web        Controller、入口、配置、Liquibase
├─ roam-vue        前端
└─ docs/
```

复用边界（来自对两个旧项目的评估）：

- **L1 直接搬**：Dijkstra/DP/拥挤度、Redis 封装、统一返回与异常、分页、限流、ES 客户端、Liquibase 写法。
- **L2 改模型后搬**：评论树、通知幂等、搜索召回与兜底、登录会话。
- **L3 重写**：内容模型、地点页、路线展示、后台。

## 8. 页面清单（10 个）

`/` 首页 · `/topic/:id` 主题页 · `/post/:id` 帖子详情 · `/nav` 导航 · `/publish` 发布 ·
`/search` 搜索 · `/user/:id` 个人主页 · `/notice` 通知 · `/login` 登录注册 · `/admin/**` 后台

后台独立入口，`/admin/**` 一律 `@Permission(ADMIN)`，普通用户 403。

## 9. 分阶段与验收

| 阶段 | 内容 | 估时 | 验收（可演示） |
|---|---|---|---|
| P0 骨架 | 仓库/模块、Liquibase、登录会话、主题与地点导入、发帖、地点页最小版 | 3–5 天 | 注册登录 → 发一条挂地点的帖子 → 地点页看到它 |
| P1 闭环 | 评论/点赞/收藏/关注/通知、首页信息流、ES 搜索 + 兜底、后台审核 | 2 周 | 完整内容闭环可走通；搜索"教三"能出帖子；审核队列可用 |
| P2 空间 | 图导入、Dijkstra + 多方案、拥挤度记录与衰减、帖子多地点排序 → 路线、评分与 rank 快照 | 1.5–2 周 | 导航页能出 2–3 条方案并按拥挤度着色；帖子能"按顺序走" |
| P3 打磨 | 20–30 条种子内容、样式、README、docker-compose、演示脚本、测试补齐 | 1 周 | 一条命令起全套；10 分钟演示脚本可复现 |

每阶段结束都必须"能独立演示"，做不完就砍该阶段非主干了内容，不允许半成品堆到下阶段。

## 10. 风险

| 风险 | 应对 |
|---|---|
| 范围膨胀 | 本章程"不做"清单是硬约束；新想法进二期清单 |
| ES/Redis/RabbitMQ 运维成本 | 全部可开关；P0 就写 compose |
| 无真实用户 | 种子内容 + 脚本压请求演示拥挤度；简历叙述如实写"设计驱动" |
| 地点数据无维护入口 | 静态导入；校园变化时走 SQL 迁移脚本 |
| 与 taco 重复度高 | 新仓库 + 新模型；能直接搬的只搬技术实现，不搬"文章"模型 |
