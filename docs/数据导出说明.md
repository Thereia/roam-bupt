## 3. 三个需要你知道的结论

### 3.1 原始 GeoJSON 没了，经纬度也没了

- 仓库里只有 6 节点的样例（`docs/spec/samples/bupt_minimal/raw/*.geojson`），不是全量。
- 库里没有任何 lat/lng 列（information_schema 查过），代码在 v2 时已把"经纬度方案"改成"底图比例坐标方案"。
- **一期按章程走比例坐标**，不影响任何功能。

### 3.2 但底图是 OSM 截图，真地图随时能回来

`travel-bupt-frontend/src/assets/map.png` 是 OpenStreetMap 的北邮西土城校区截图（图上带 "© OpenStreetMap contributors"）。所以有两条后路，都不用重新采点：

1. **地理配准**：在图面取 2–3 个已知地标（主教学楼、体育场、校门），解一个相似变换，就能把 372 个 `x_ratio/y_ratio` 批量换算成经纬度；
2. **直接重建**：用 Overpass 拉北邮 bbox 的 `highway=footway/path/service` 路网，得到带真实坐标的图，和现有图二选一。

二期要做真地图时，第 1 条成本最低（半天），第 2 条数据更干净但要重新校对地点。

### 3.3 地点数据需要一次人工过筛

能直接用的 67 个里，还缺：菜品种类、营业时间、楼层、简介。这些 P0 先留空，P3 补种子内容时顺手填一批重点项目（食堂、图书馆、教三）。

## 4. 导入映射（P0 Liquibase）

```
campus_poi.poi_id        → topic.source_ref（保号，便于回溯）
campus_poi.poi_name      → topic.name
campus_poi.poi_category  → topic.category（先存原值，展示分类另做映射）
campus_poi.node_id       → topic.node_id（导航入口）
campus_poi.heat_score    → topic.heat
campus_poi.enabled       → topic.enabled（教室/卫生间强制置 0）
                        → topic.type = 'PLACE'

route_node / route_edge  → 原样导入，node_id / edge_id 保留原号段
```

建议 `topic.id` 直接用 `source_poi_id`（1–145），分类主题从 1000 起，避免自增映射错位。

## 5. 已知问题（P0 不阻塞）

| 问题 | 影响 | 处理 |
|---|---|---|
| 地点无封面/描述 | 地点页顶部空 | P3 补，或用底图截取该地点区域当封面 |
| 热度几乎全 0 | 首页"这周人多的地方"没数据 | 种子内容发布后自然累积；演示前可跑脚本灌热度 |
| 评分全 0 | 地点页显示 0 分 | 种子用户打分或 P3 脚本灌入 |
| `building_id` 全相同 | 室内导航用不上 | 不做室内，忽略 |
| 教室/卫生间混在 145 里 | 地点页出现房间号 | 导入时 `enabled=0` |
